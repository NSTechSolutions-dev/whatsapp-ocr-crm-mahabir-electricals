Mahabir CRM — Automation Data Flows

How the four WhatsApp automations are triggered, filtered, queued, and delivered. Generated from the production backend automation services.

Overview

All automations end in the same delivery path: a BullMQ job on automationQueue → worker in automation.job.ts → sendTemplateMessage (MSG91) → outbound WhatsApp message in the customer inbox.

  1. Inquiry Follow-up — delayed after quotation send
  2. Price Drop Alert — event-driven on inventory rate change
  3. Repeat Engagement — daily cron for inactive pipeline leads
  4. Last Inquiry Reminder — daily cron for unanswered sent quotes

Shared architecture

flowchart LR
  Trigger[Trigger source] --> Filter[Eligibility filters]
  Filter --> Queue[BullMQ automationQueue]
  Queue --> Worker[automationWorker]
  Worker --> WA[sendTemplateMessage MSG91]
  WA --> Inbox[WhatsAppMessage OUTBOUND in Conversation]
  Worker --> JobRow[ScheduledJob COMPLETED or FAILED]

1. Inquiry Follow-up

Trigger typeinquiry_followup
WhenImmediately after quotation is sent
DelayN days (default 3)
Templatemahabir_inquiry_followup
Variables{{1}} name, {{2}} quote number

When staff send a quotation (enquiry page, quotation page, or saved-template send), the system schedules a delayed follow-up for each active inquiry_followup rule. The message only goes out if the customer has not replied since the quote was sent.

Data flow

sequenceDiagram
  participant User as Staff / Send API
  participant Send as sendQuotation
  participant Sched as scheduleInquiryFollowup
  participant DB as Postgres
  participant Redis as BullMQ delay
  participant Worker as automationWorker
  participant WA as MSG91 WhatsApp

  User->>Send: POST /quotations/:id/send
  Send->>WA: Send PDF quotation template
  Send->>DB: enquiry status SENT, quotation.sentAt
  Send->>Sched: For each active inquiry_followup rule
  Sched->>DB: Create ScheduledJob PENDING
  Sched->>Redis: Add job inquiry_followup with delay N days
  Note over Redis: Waits N days
  Redis->>Worker: Job due
  Worker->>DB: Load enquiry + quotation
  alt quotation not SENT or no sentAt
    Worker->>DB: Mark skipped
  else customer sent INBOUND after sentAt
    Worker->>DB: Mark skipped customer_replied
  else eligible
    Worker->>WA: mahabir_inquiry_followup
    Worker->>DB: ScheduledJob COMPLETED + inbox message
  end

Skip conditions (at send time)

  • Rule inactive or customer missing
  • Quotation not in SENT status / missing sentAt
  • Customer already replied (inbound message after sentAt)

2. Price Drop Alert

Trigger typeprice_drop_alert
WhenInventory rate is lowered
ThresholdOptional % drop (default 0 = any drop)
WindowLatest enquiry within maxInquiryAgeDays (default 30)
Templatemahabir_price_drop
Variablesname, product, old rate, new rate

When an inventory product rate is updated downward, triggerPriceDrop finds customers who previously had that product on an enquiry and notifies them — if they are not Closed and their latest enquiry is recent enough.

Data flow

flowchart TD
  A[Admin updates inventory rate] --> B{newRate less than oldRate?}
  B -->|No| Z[Exit no jobs]
  B -->|Yes| C[Load active price_drop_alert rules]
  C --> D[Find EnquiryItems with this inventoryId]
  D --> E[Unique customerIds from those enquiries]
  E --> F{Drop percent meets threshold?}
  F -->|No| Z
  F -->|Yes| G[For each customer]
  G --> H{stage is Closed?}
  H -->|Yes| Skip[Skip]
  H -->|No| I{Latest enquiry within maxInquiryAgeDays?}
  I -->|No| Skip
  I -->|Yes| J[enqueueAutomationJob price_drop_alert]
  J --> K[Worker sends mahabir_price_drop]
  K --> L[Inbox OUTBOUND + ScheduledJob COMPLETED]

Key filters

  • Only fires when newRate < oldRate
  • Optional minimum drop % via triggerParams.threshold
  • Customer stage must not be Closed
  • Latest enquiry must be newer than maxInquiryAgeDays

3. Repeat Engagement

Trigger typerepeat_engagement
WhenDaily cron (default 09:00 IST)
Inactive periodinactiveDays (default 30)
StagesLead, Contacted, Proposal, Negotiation
Templatemahabir_repeat_engagement
Variables{{1}} customer name

A node-cron job (Asia/Kolkata) runs once per day. It finds customers still in open pipeline stages whose latest enquiry is older than the inactive window, and who have not already been messaged by this rule in that window.

Data flow

sequenceDiagram
  participant Cron as node-cron IST
  participant Svc as triggerRepeatEngagement
  participant DB as Postgres
  participant Q as automationQueue
  participant Worker as automationWorker
  participant WA as MSG91

  Cron->>Svc: Daily tick at scheduleTime
  Svc->>DB: Active repeat_engagement rules
  loop Each customer in configured stages
    Svc->>DB: Latest enquiry
    alt No enquiry OR enquiry newer than inactiveDays
      Svc-->>Svc: Skip
    else Already has ScheduledJob in window
      Svc-->>Svc: Skip dedupe
    else Eligible
      Svc->>Q: enqueue repeat_engagement
    end
  end
  Svc->>DB: recordCronTick summary
  Q->>Worker: Process job
  Worker->>WA: mahabir_repeat_engagement
  Worker->>DB: COMPLETED + inbox message

Eligibility

  • Customer stage in configured open stages
  • Latest enquiry createdAt ≤ now − inactiveDays
  • No recent PENDING/PROCESSING/COMPLETED job for this rule+customer since cutoff

4. Last Inquiry Reminder

Trigger typeenquiry_reminder
WhenDaily cron (default 09:00 IST)
AgedaysSinceSent (default 7)
StagesAny except Closed
Templatemahabir_enquiry_reminder
Variables{{1}} name, {{2}} quote ref

Daily cron finds non-Closed customers whose most recent sent quotation is older than N days and who have not replied since that send. Reminds them about that quote.

Data flow

flowchart TD
  Cron[Daily cron enquiry_reminder] --> Rules[Load active rules]
  Rules --> Cust[Customers where stage not Closed]
  Cust --> Last[Find latest SENT enquiry with quotation.sentAt]
  Last --> Age{sentAt older than daysSinceSent?}
  Age -->|No| Skip[Skip]
  Age -->|Yes| Reply{Inbound message after sentAt?}
  Reply -->|Yes| Skip
  Reply -->|No| Dedupe{Recent job for rule+customer?}
  Dedupe -->|Yes| Skip
  Dedupe -->|No| Enq[enqueue enquiry_reminder]
  Enq --> Worker[Worker checks rule active and stage]
  Worker --> Send[send mahabir_enquiry_reminder]
  Send --> Done[Inbox + ScheduledJob COMPLETED]

Eligibility

  • Customer stage ≠ Closed
  • Has a SENT enquiry with quotation.sentAt
  • sentAt is older than daysSinceSent
  • No inbound reply after that sentAt
  • No recent execution of this rule for the customer in the same window
